## 一、正式版（直接贴简历）

**CustLens 客户洞察与精准营销平台 | 独立项目 | 项目链接（含 9 页界面截图与运行说明）**　2026.11–至今

- **需求拆解与方案设计**：面向「运营拿到客户表不会分层圈人」的通用场景，拆出数据接入、客户画像、客户分层、响应预测、方案生成 5 个能力；用字段自动识别（别名匹配 + 内容校验）替代固定模板，同一套流程跑通 2205 行客户宽表与 54 万行订单明细（聚合 4373 位客户），无需改代码。
- **算法落地与效果验证**：实现 RFM 八分层、KMeans 客群聚类（标准化 + 轮廓系数选 K）、逻辑回归响应预测（类别加权 + F1 网格搜索阈值，验证集 AUC 0.883、F1 0.598）、Apriori 品类关联；Top 10% 名单响应率为均值的 4.51 倍，重要价值客户占 35.4% 却贡献 56.3% 营收。
- **结论与营销策略自动化**：用规则引擎把模型指标翻译成「证据 + 建议动作」的业务结论（价值集中度、沉默预警、品类与渠道结构、折扣依赖等 9 类），再按预算 ÷ 触达成本圈人并依响应概率排序，结合品类偏好、渠道贡献与购买间隔生成选品、渠道、时机与话术，输出 ROI 预估（示例方案 7.19）。
- **工程化与交付**：基于 FastAPI + pandas/scikit-learn 提供 22 个 REST 接口，上传走「先试读、后应用」两阶段避免误覆盖线上数据；React + ECharts 实现 9 页看板，前端按数据能力自动隐藏页面与指标列而非显示占位；Nginx + Docker Compose 一键部署，GitHub Actions 三版本矩阵执行 52 项数据契约测试与 21 项接口冒烟测试，产物固定时间戳实现字节级可复现，仓库 MIT 开源。

## 三、自我介绍口述版（30 秒）

> 我做了个客户数据分析平台 CustLens。业务问题是：运营拿到客户数据，不知道怎么分层、不知道先联系谁。
> 上传一份客户表或订单表，平台自动识别字段，算出每个客户的 RFM 与消费特征，用 KMeans 分群、逻辑回归预测谁最可能响应活动，最后直接给出营销方案：圈多少人、推什么品类、走哪个渠道、什么时候推、预计 ROI。
> 关键数字是响应预测 AUC 0.883，Top 10% 名单的响应率是平均值的 4.5 倍；做了 52 项数据契约测试，换一份客户数据也能直接跑。

## 四、面试追问（一句话答案）

| 问题 | 回答要点 |
|---|---|
| 为什么用逻辑回归不用 XGBoost？ | 数据量 2000 行、特征十几个，更需要能解释「什么在驱动响应」的系数；类别加权解决 15% 正样本的不平衡。 |
| 轮廓系数 0.216 是不是太低？ | 低，消费行为数据上常见；我把它当分层参考而非硬分类，界面与文档如实标注，再用 RFM 规则分层交叉验证。 |
| 阈值 0.78 怎么定的？ | 验证集上以 F1 最大为目标网格搜索 0.05–0.80 得到；高阈值换来更高精确率（0.69），符合「预算有限、少打扰」的业务偏好。 |
| 换一家公司的数据还能跑吗？ | 能。字段识别靠别名 + 内容校验而非写死列名，粒度自动判定，缺什么能力就隐藏对应页面；已用 4 份公开数据实测。 |
| 这是 demo 还是能上线的？ | 可运行产品：前后端分离、Nginx + Docker 部署、CI 自动测试与容器健康检查；认证与多租户属于下一步。 |
